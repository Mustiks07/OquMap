# Проверенный демонстрационный сценарий

## Для жюри: «Демо за 3 минуты» (`/demo-3min`)
Один клик «Открыть демо» создаёт одноразовую копию демо-организации (синтетические данные, TTL 6 ч) и открывает
обзор. Пункт меню «Демо за 3 минуты» — режим только для просмотра: перед показом выполняется preflight (данные,
обзор, граф, сравнение, план, режим ИИ — каждый пункт реальным вызовом сервиса), затем 7 экранов. На каждом —
три блока: «Что обнаружено», «Почему можно доверять», «Что делать дальше». Шаг сохраняется при перезагрузке;
«Сбросить демо» выдаёт новую одноразовую копию. Проверяется `tests/e2e/wow.spec.ts` (локально и в Docker).

| № | Экран | Что видно (синтетический корпус `base`, seed фиксирован) |
|---|---|---|
| 1 | Где проблема | T3 — 47,1% (802 уч., 32 кл.), самая низкая из измеренных; T6/T8 без надёжного измерения не показаны как 0% |
| 2 | Цепочка доказательств | T3 → цель 3.2 (43,3%) → задание I20 (37,4%) → гипотеза «ошибка при занимании единицы» (27,4%, 220 уч.) → пособие А с. 15 → 14 ч в плане → **пробел «по теме нет решения»**; клик по узлу открывает строки ответов / расчёт / страницу |
| 3 | Сравнение пособий | Сырая разница B − A = −5,3 п.п., после стандартизации по входному уровню +5,2 п.п. (95% ДИ ≈ +1…+9 п.п.) — знак меняется |
| 4 | Консилиум | Критик **блокирует** вывод по сырой разнице («группы различаются по входному уровню»), ослабляет скорректированную разницу до «связи, не эффекта пособия» и гипотезу ошибки; итоговая карточка с проверенными ID и числами |
| 5 | Сценарии часов | «добавь 2 часа на T3 за счёт T7» → `add T3 2; remove T7 2` → A: T3 14→16, T7 12→10, валидатор ✓; B «T3 = 30» → **ограничения несовместимы** (T3 ≥ 30 и T3 ≤ 20) — показан конфликт, а не тихое исправление |
| 6 | Диагностика | 3 задания на найденные гипотезы; ключ пересчитан точно, каждый дистрактор — применение правила ошибки; предпросмотр ничего не сохраняет |
| 7 | Решение | Есть ли решение по теме (пробел графа), как его утвердить и проверить повторно без «причинного процента» |

Режим ИИ виден в шапке тура: без ключа — «Шаблон без модели» (роли консилиума — шаблоны, критик — правила).
Записанного прогона живой модели нет: ключа в среде разработки не было, выдумывать «записанный ответ модели» не стали.
При настроенном провайдере (см. README → «Модель и OCR») роли Аналитика и Эксперта отвечают живой моделью для
синтетических данных; их утверждения проходят те же проверки ID и чисел.

## Полный путь методиста

Этот путь автоматически проходит `tests/e2e/scenario.spec.ts` (Playwright, проверено 11.11.2026 на локальном стеке
и на Docker Compose). Числа ниже — из свежего синтетического корпуса `base` (seed фиксирован); на экране они
вычисляются, а не берутся из этого текста.

| Шаг | Действие | Что видно и что это доказывает |
|---|---|---|
| 1 | «Открыть демо» (методист) → набор «Основной демо-корпус» | Метка «Синтетические данные», версия данных v1 |
| 2 | «Импорт и качество» | 802 ученика, 32 класса, 8 школ; пропуски, отсутствия и строки повторных попыток по каждой проверке; что доступно и чего не хватает |
| 3 | «Обзор тем» | T3 — первая в приоритетах (≈47%, интервал по классам); T6 «разметка не подтверждена», T8 «не измерялась» — не нули; темы × классы |
| 4 | Переключить KZ → RU | Фильтры (например, «последняя попытка») сохраняются; меню и подписи на казахском (перевод не проверен специалистом) |
| 5 | «Разобрать тему» T3 | Цели, задания с распределением ответов, гипотезы ошибок («не домножает числители», «складывает числители и знаменатели»), кнопка интерпретации (`recorded_demo`), источники с печатной страницей |
| 6 | «Сравнение изданий» | Исходно A 49,8% > B 44,5% (−5,3 п.п.); после стандартизации A 44,5% < B 49,6% (+5,2 п.п., 95% интервал ≈ +1…+9 п.п.); предупреждение «направление изменилось»; уровень «скорректированная связь (не причинный вывод)» |
| 6а | Раскрыть «Как работает стандартизация» | 144/180, 8/20 vs 18/20, 108/180 → 76%/63% и 60%/75%, вычислено из фикстуры |
| 6б | (по желанию) выбрать наборы «Разные тесты» / «Пособие совпадает с учителем» / «Мало классов» | «Рейтинг недопустим» / «Несопоставимо» / «интервал не рассчитывается» с причинами |
| 7 | «Планировщик часов» → «Рассчитать план» | Три сценария; в сбалансированном T3 14→16 ч при сумме 102; «все ограничения проверены независимым валидатором»; пометка «тема не измерена — нужна диагностика» |
| 7а | Вкладка «Учебный модуль 20 ч»: зафиксировать R, CONS, CHECK, мин. TARGET = 10 | «Ограничения несовместимы»: проверенный минимальный набор (бюджет 20, R зафиксирована на 4, TARGET ≥ 10, CONS ≥ 3, CHECK ≥ 4) + «сумма нижних границ 21 ч при бюджете 20 ч». Минимальных наборов может быть несколько; показывается один, каждый элемент которого перепроверен |
| 8 | «Решение и отчёт» → «Заполнить черновик рекомендацией» → ответственный → «Сохранить» | Снимок: показатели, сравнение, изменение часов, источники, ограничения; режим `template` подписан |
| 9 | «Утвердить» | Версия 2 «Утверждено», версия 1 «заменена»; история сохранена |
| 10 | «Отчёт PDF» / CSV / XLSX | PDF с меткой синтетических данных, числа совпадают со снимком |
| 11 | В карточке: загрузить `data/demo/imports/followup_2026_2027.csv` → «Загрузить» | Новая версия данных v2; карточка помечена «данные изменились», снимок не меняется |
| 12 | «Рассчитать динамику» | «Есть положительный сигнал» (≈ +5–6 п.п. на 13 общих заданиях, интервал выше 0) с подписью «наблюдаемая динамика, не оценка воздействия» |
| 13 | «Ассистент» → «Какие данные подтверждают проблему?» | Ответ с текущими фильтрами, режимом и вызванными функциями |

Ограничение демонстрации: если в шаге 8 задать фильтр «Издания = A», повторная проверка показывает и группу
сравнения (B) с описательной «разницей изменений».
