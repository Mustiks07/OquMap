# OquMap — аудит шрифтов RU/KZ

## Вывод

Основной кандидат для продукта — **Onest 2.x Variable**, локально размещённый в приложении, с `Noto Sans` как системным fallback. Для технических идентификаторов и при необходимости строгих табличных чисел можно использовать отдельный mono-стиль, но не смешивать два шрифта в обычном интерфейсном тексте.

Причина выбора Onest:

- проект прямо заявляет поддержку казахского языка и расширил кириллицу до 56 языков;
- шрифт разработан для экранного чтения, интерфейсов и навигации в малом кегле;
- variable weight 100–900 позволяет настроить спокойную иерархию без лишних файлов;
- включает кириллицу-ext, математические символы и дроби;
- SIL Open Font License 1.1 допускает self-hosting и распространение вместе с приложением;
- характер менее обезличенный, чем у стандартного Inter/Segoe UI, но остаётся профессиональным.

## Проблема текущего проекта

В `tokens.css` задан стек:

```css
"Inter", "Segoe UI", "Roboto", "Noto Sans", "DejaVu Sans", system-ui, sans-serif
```

Но Inter не подключён через `@font-face`, пакет или preload. На обычном Windows-показе фактическим шрифтом будет Segoe UI. Поэтому дизайн сейчас зависит от машины, а screenshots, проектор и deployed build могут выглядеть по-разному.

## Кандидаты

### 1. Onest 2.x — основной выбор

Характер: современный геометрически-гуманистический гротеск, открытый, спокойный, с заметной индивидуальностью.

Лучшее применение:

- основной продуктовый текст;
- navigation и controls;
- заголовки 20–36 px;
- длинные выводы и методические объяснения;
- RU/KZ интерфейс из одного файла.

Рекомендация:

```css
--font-sans: "Onest", "Noto Sans", system-ui, sans-serif;
font-optical-sizing: auto;
font-synthesis: none;
```

Рабочие веса: 430 body, 520 labels, 580 headings, 650 только для редкого сильного акцента. Не использовать повсеместно 700.

### 2. IBM Plex Sans — Scientific Instrument

Характер: исследовательский, технический, точный. Хорошо работает с большим количеством таблиц и подписей; Plex Mono создаёт аккуратный технический второй голос.

Плюсы:

- спроектирован для UI;
- большое семейство Sans/Serif/Mono/Condensed;
- extended Cyrillic и OFL;
- сильная система для аналитического продукта.

Риск: перед финальным выбором нужно прогнать весь казахский glyph set и kerning в реальном браузере. Если отдельный символ отсутствует, fallback внутри слова даст заметную разницу. Поэтому для этой системы обязателен automated glyph check и визуальный specimen.

### 3. Source Sans 3 — Civic Humanist

Характер: нейтральный гуманистический интерфейс, очень читаемый, менее «технологичный» и более общественно-институциональный.

Плюсы:

- официальный проект подтверждает Kazakh Cyrillic;
- open-source/OFL;
- подходит для длинных текстов, отчётов и интерфейсов государственных/образовательных систем;
- хорошие формы букв в малых размерах.

Минус: менее выраженная фирменная индивидуальность; её придётся создавать сеткой, типографическим масштабом и графикой.

### 4. Inter — контрольный вариант, не финальный выбор по умолчанию

Характер: максимально привычный продуктовый grotesk, отличная читаемость на экране, tabular numbers и variable font.

Плюсы:

- предсказуем в интерфейсах;
- хорошие цифры и OpenType-функции;
- OFL.

Минусы:

- слишком распространён и легко делает продукт похожим на шаблон;
- текущая версия проекта его не загружает;
- точное покрытие казахских букв и качество их форм нужно проверять на выбранном релизе, а не предполагать по общему слову «Cyrillic».

### 5. Noto Sans — обязательный fallback

Noto Sans официально поддерживает `kk_Cyrl` и широкий кириллический набор. Он может быть самостоятельным безопасным выбором, но для OquMap лучше использовать его как проверенный fallback и шрифт для редких Unicode-символов.

## Рекомендуемая система OquMap

### Product UI

- Onest Variable;
- 14/20 body;
- 13/18 compact data;
- 12/16 metadata;
- 24/30 page heading;
- 36/40 investigation question;
- tracking отрицательный только от 24 px;
- `font-variant-numeric: tabular-nums lining-nums` для метрик и таблиц;
- числа выравниваются по правому краю;
- знак минуса используется математический `−`, не дефис `-`.

### Reports and exports

PDF/HTML/XLSX должны использовать тот же визуальный ритм. Если генератор PDF не умеет Onest Variable, встраивается статический Onest Regular/Medium/SemiBold либо Noto Sans как полностью покрывающий fallback. Нельзя молча переходить на Helvetica и получать другой документ.

### Mono

Mono применяется только к dataset IDs, checksums, версиям, логам и техническим формулам. Проценты, часы и результаты остаются в Onest с tabular figures — иначе интерфейс распадается на два голоса.

## Обязательный specimen

Перед внедрением отрисовать на Windows/Chrome, Linux/Chromium и в PDF:

```text
Почему проседают дроби?
Оқу картасы — әдістемелік шешім
Әә Ғғ Ққ Ңң Өө Ұұ Үү Һһ Іі
Қате → мақсат → оқулық → нәтиже
62%  −18 п.п.  +2 часа  1 234,56  ⅓  ≤  ≥  ≈
```

Проверить:

1. все казахские glyphs из одного шрифта;
2. отсутствие скачков baseline и x-height;
3. tabular widths 0–9;
4. различимость `І`, `I`, `1`, `l`, `О`, `0`;
5. кавычки, тире, минус, стрелки и математические знаки;
6. веса 400–650 и отсутствие synthetic bold;
7. переносы длинных казахских меток;
8. совпадение web и PDF;
9. отсутствие FOIT/FOUT на первом экране;
10. локальное размещение без внешнего font CDN.
