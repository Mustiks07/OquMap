# Реализация, повторное измерение и организационное обучение

Код: `services/fidelity.py` (`fidelity-v1`), `services/learning_loop.py` (`loop-v1`), `services/portfolio.py`.
Тесты: `tests/test_fidelity.py`, `tests/test_learning_loop.py`. Экраны: `/pilots/:id/fidelity`,
`/pilots/:id/follow-up`, `/portfolio/interventions`.

## 1. Журнал реализации (fidelity)
Запись: класс, дата (в периоде пилота и не в будущем), плановые/проведённые минуты, активности план/факт,
выполненные задачи, присутствовали/назначены, чек-лист соблюдения, адаптация, срыв/отмена и причина, источник,
кто записал, время. Записи **только добавляются**; исправление — новая запись с `corrects_log_id`, исходная
остаётся в истории (`superseded_by`) и исключается из расчёта. Журнал ведётся для активного или завершённого пилота.

Агрегаты по каждому классу интервенции и по пилоту (суммарно), на дату `as_of` (по умолчанию — окончание
завершённого пилота или сегодня):
* ожидаемые занятия = плановые (в неделю × недель) × доля прошедшего периода;
* покрытие журналом = записано / ожидалось; пропущенные записи = ожидалось − записано;
* дозировка = Σ проведённых минут / (ожидаемые × плановые минуты) — отсутствующая запись считается как 0 минут;
* занятия = проведённые (не отменённые) / ожидаемые; охват = Σ присутствовали / Σ назначены;
* соблюдение = (отмеченные пункты чек-листа + выполненные активности) / (пункты + плановые активности).

Классификация (`rule_set` в ответе): `unknown` — ничего ещё не ожидается или покрытие < 50% (нехватка записей не
выдаётся за низкую реализацию); `low` — дозировка, занятия или соблюдение < 50%; `high` — все доступные
показатели ≥ 80%; иначе `moderate`. Итог пилота понижается с `high` до `moderate`, если ≥ 1/3 классов `low`/`unknown`.

## 2. Повторное измерение (`POST /pilots/{id}/follow-up`)
1. **Сопоставимость**: одна форма → все задания цели/темы пилота; одна шкала с методом связывания → только общие
   задания; иначе `invalid_due_to_comparability` (изменение не считается). Используются только подтверждённые
   связи заданий с целями.
2. **Шкала**: доля баллов ученика на заданиях пилота (0–1), правила попыток/пропусков из плана анализа.
3. **Пары**: только ученики классов пилота с баллом в обоих измерениях; отсев по группам (отсутствовал до/после,
   нет балла), различие отсева между группами > 10 п.п. — предупреждение.
4. **Оценка**: среднее парное изменение; кластерно-устойчивая SE по классам и интервал t(G−1) только при ≥ 5
   классах в группе. Для дизайнов со сравнением — разница средних изменений, SE = √(SE²₁ + SE²₂),
   df = min(G₁, G₂) − 1. Поправка (прямая стандартизация изменений по стратам входного балла с общими весами,
   перцентильный кластерный бутстрэп 1000 повторов, фиксированный seed) — **только если указана в плане анализа**;
   пустая страта → поправка не выдаётся. Сырой и скорректированный результаты возвращаются оба; основной —
   по плану.
5. **Неоднородность**: доля классов интервенции с отрицательным изменением; строки по классам с n < 10 скрыты и
   видны только ролям с доступом к данным классов.

### Статусы (правила применяются по порядку, сработавшие возвращаются в `status_rules_fired`)
| # | Условие | Статус |
|---|---|---|
| 1 | измерения несопоставимы / нет общих заданий | `invalid_due_to_comparability` |
| 2 | нет итогового измерения | `needs_more_data` |
| 3 | дизайн без реализованного анализа (ITS, stepped wedge) | `needs_more_data` |
| 4 | сопоставленных учеников меньше минимума плана (30) | `needs_more_data` |
| 5 | реализация `low` или `unknown` | `invalid_due_to_fidelity` — **никогда не «интервенция не работает»**, даже при отрицательном изменении |
| 6 | отсев > 40% | `needs_more_data` |
| 7 | интервал недоступен | `needs_more_data` |
| 8 | нижняя граница > 0 | `positive_signal`; при реализации `moderate` или неоднородности — `mixed` |
| 9 | иначе | `not_confirmed` (при верхней границе < 0 — с пометкой `negative_change_observed`) |

**Уровень вывода** выводится из дизайна и проверок, а не из «уверенности» модели: `none` для статусов 1–7;
`descriptive_change` для одной группы; `adjusted_association` для подобранного сравнения только с заранее
заданной поправкой (иначе `descriptive_comparison`); `causal_estimate` для кластерной рандомизации только при
записанной серверной рандомизации, высокой реализации, отсеве ≤ 20%, без различающегося отсева и дисбаланса входа.
Результат неизменяем: одинаковые входы (снимок, план, измерение, версия данных, журналы, метод) → тот же
`PilotOutcome`. Для активного пилота результат помечается `interim`.

## 3. Вывод и следующий цикл (`POST /pilots/{id}/conclusions`)
Человек сохраняет: решение `continue | modify | stop | extend_data_collection`, вывод, чему научились, открытые
вопросы, основания (`evidence_ids` — результат пилота, записи журнала, снимки анализа или фрагменты источников
организации; чужие/несуществующие → 404). Опционально:
* **следующая версия решения** — новая версия в группе связанного `Decision` (или первая версия новой группы) в
  статусе `draft` со снимком `learning_loop`; утверждение — обычным процессом решений;
* **запись доказательной базы** интервенции (`proposed`), которая попадает в сводку и подбор только после
  принятия утверждающим (`POST /intervention-evidence/{id}/review`). Версия интервенции при этом не меняется.
Решение «остановить» после `invalid_due_to_fidelity` требует объяснить, что причина — реализация, а не доказанная
неэффективность; принятие неинтерпретируемого результата в базу требует заметки.

`GET /learning/summary` — чему организация научилась: выводы, открытые вопросы, записи на рассмотрении,
принятые сигналы по интервенциям. Автоматического «обучения политики» нет.

## 4. Портфель (`GET /portfolio/interventions`)
Счётчики по статусам, просроченные и ближайшие повторные измерения, распределения реализации и результатов,
интервенции с ≥ 2 принятыми сопоставимыми положительными сигналами (сравнительный дизайн, высокая реализация),
покрытие тем пилотами и интервенциями, чего не хватает для вывода, очередь действий. Рейтингов школ/учителей нет;
`best_intervention = null` (`not_shown_without_comparability_and_repetition`).

## 6. Раунд 2
### 6.1 Дата расчёта (`as_of`)
`effective_as_of = as_of` (явная; в будущем — `422 as_of_in_future`) или значение по умолчанию: для пилота после
окончания — дата окончания, поднятая до даты итогового измерения; иначе сегодня (`services/clock.py`). Эта дата входит
в отпечаток результата, используется в расчёте реализации и сохраняется в результате (`as_of`). Измерение позже
`as_of` → `422 outcome_after_as_of`. Одинаковая явная дата без новых журналов переиспользует результат. Портфель
передаёт свой `as_of` во все расчёты реализации и в список пилотов (статусы и результаты — текущие записи).
Тесты: `tests/test_asof.py`.

### 6.2 Синтетические и реальные доказательства
Записи доказательной базы делятся на реальные и синтетические (по признаку пилота/набора). В рекомендации и
«повторный сигнал» входят только **принятые реальные** записи; синтетические показываются отдельным компонентом с
0 баллов (`synthetic_demo_signals`) и отдельным блоком портфеля — независимо от того, демо ли организация.

### 6.3 Структурированный вывод
`decision_basis` (`evidence_supports | operational | insufficient_evidence | external_factors`), `stop_reason_code`,
`acknowledged_limitation_codes` (стандартные признания или коды ограничений этого результата). Текст вывода не
проверяется. После неинтерпретируемого результата «остановить» допустимо только как операционное решение с
признаниями `no_effectiveness_conclusion` и `requires_new_pilot_or_implementation`; основание
`evidence_supports` для такого результата запрещено.

### 6.4 Подавление малых групп
Для ролей без доступа к данным классов (viewer/analyst): группа результата с < 10 сопоставленными учениками скрывается,
а основная оценка, отсев и общее число — тоже (иначе скрытое восстанавливается вычитанием); строки по классам удалены.
Портфель: ученики по статусам результата с первичным и дополнительным скрытием. `suppression` в ответе описывает,
что скрыто и почему.

### 6.5 Реализация по календарю
Если у пилота есть календарь занятий, ожидаемые занятия = запланированные до `as_of`, кроме перенесённых (их заменяет
новое занятие), плановые минуты = их длительности (`expected_source = calendar`); иначе — равномерное правило
(`uniform`). Состояние календаря входит в отпечаток результата.
