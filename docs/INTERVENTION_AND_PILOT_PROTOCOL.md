# Библиотека интервенций и протокол пилота

Код: `services/interventions.py`, `services/pilots.py`, модели `oqumap/measurement_models.py`
(миграция `c2a7e5f1b3d9`), маршруты `api/intervention_routes.py`. Тесты: `tests/test_interventions.py`,
`tests/test_pilots.py`. Экраны: `/interventions`, `/interventions/:id`, `/pilots/new`, `/pilots/:id`.

## 1. Интервенция
* **Идентичность** (`interventions`): организация, необязательная привязка к набору, код (уникален в организации),
  статус `active | archived`, причина/время архивирования.
* **Версия** (`intervention_versions`): название и описание RU/KZ, классы и языки применимости, минуты × занятий в
  неделю × недель (+ частота текстом), инструкция, ресурсы, уровень доказательств
  `practice_based | observational | experimental`, ссылки на источники (`http(s)://`, `doc:`, `source:`),
  противопоказания и ограничения, цели (`topic | objective | misconception`), автор, рецензент, `content_sha256`.
* Жизненный цикл версии: `draft → reviewed`; черновик редактируется (`PATCH`, с `expected_version` против
  конфликтов) и удаляется физически, **только если ни один пилот на него не ссылается**. `reviewed` неизменяема:
  `PATCH`, добавление цели и удаление → `409 version_immutable`; изменения — `POST …/versions` (новый черновик с
  копией содержания и `change_note`). Архивирование интервенции переводит черновики в `archived`, сохраняя
  рецензированные версии, историю и снимки в пилотах; новые пилоты с архивной интервенцией не создаются.
* Рецензирование требует инструкцию и хотя бы одну цель.
* Цели проверяются по программе организации (чужая тема/цель → 404); коды типичных ошибок — по каталогу.
* Текстовые поля очищаются от управляющих символов и ограничены по длине.

### Подбор (`GET /interventions/suggest`)
Только **рецензированные** версии **активных** интервенций. Балл — сумма объяснённых компонентов
(`scoring_rule` в ответе): совпадение с ошибкой +3, с целью +2, с темой +1, применимость к классу/языку +0,5,
уровень доказательств experimental +1 / observational +0,5, принятые человеком положительные сигналы +0,5 каждый
(не более +1). Неприменимые и исключённые возвращаются с причиной. Балл — соответствие проблеме, а не прогноз
прироста; изменения рекомендаций происходят только через записи, принятые человеком.

## 2. Пилот
Протокол фиксирует: снимок версии интервенции (+ sha256), классы и группу (`intervention | comparison`, волна),
единицу назначения (`cohort | school`), дизайн, входное и итоговое измерения (итоговое может быть добавлено при
повторном измерении), даты и срок повторного измерения, ответственного, плановую дозировку (по умолчанию из
версии), критерии включения/исключения, план анализа (`adjustment none | baseline_strata`, схема страт,
правила попыток/пропусков, минимум сопоставленных учеников), предел вывода.

### Дизайны и серверные проверки (переход в `ready`/`active`)
| Дизайн | Требования | Предел вывода |
|---|---|---|
| `single_group` | нет классов сравнения; входное измерение | `descriptive_change` |
| `matched_comparison` | есть классы сравнения; входное измерение | `descriptive_comparison`; `adjusted_association`, если поправка заранее указана |
| `cluster_randomized` | назначение выполнено **сервером** (`POST /pilots/{id}/randomize`, seed записан) и не изменялось; ≥ 5 кластеров в каждой группе | `causal_estimate` (понижается при проверке результата) |
| `stepped_wedge` | серверная рандомизация волн; ≥ 2 волн | `causal_estimate` (анализ не реализован, см. LEARNING_LOOP) |
| `interrupted_time_series` | ≥ 3 измерений до начала | `quasi_experimental_trend` (анализ не реализован) |

Общие: обязательные поля, окончание не раньше начала, входное измерение не позже начала, классы из набора пилота,
при назначении по школам все классы школы в одной группе, версия интервенции рецензирована, интервенция не в
архиве. Предупреждения: класс уже в другом активном пилоте; одна группа не даёт причинного вывода; группа
сравнения не случайна.

### Статусы
`draft → ready` (методист; протокол валиден) · `ready → draft` (методист) · `ready → active` (утверждающий;
повторная проверка протокола и совпадения снимка с рецензированной версией) · `active → completed` (методист или
утверждающий) · `draft|ready|active → stopped` (утверждающий, причина обязательна). `completed` и `stopped` —
конечные. Любой другой переход → `409 invalid_transition`; недостаточная роль → `403`. Протокол и снимок
меняются только в `draft`; ручное изменение назначения сбрасывает запись рандомизации.

## 3. Права
| Действие | Роль |
|---|---|
| Чтение библиотеки, пилотов, агрегатов, портфеля, качества | любой участник организации (в т. ч. `viewer`/`analyst`) |
| Черновики интервенций и пилотов, рандомизация, журнал реализации, повторное измерение, выводы | `methodist` (журнал — также `teacher`) |
| Рецензирование/архивирование интервенций, запуск и остановка пилотов, принятие записей доказательной базы | `approver` |
| Данные по отдельным классам (журналы, строки результата) | `methodist`, `approver`, `teacher` |
`admin` проходит любые проверки (как в существующей модели). Роль `analyst` в демо-сиде отсутствует; она
поддерживается как обычная роль чтения. Аудит фиксирует действия без свободного текста заметок.

## 4. Раунд 2: инварианты, целостность, календарь, Design Studio

### 4.1 Дополнительные серверные проверки протокола
| Код | Правило |
|---|---|
| `follow_up_before_end` | срок повторного измерения не раньше окончания |
| `outcome_before_start` | итоговое измерение не раньше начала |
| `duration_calendar_mismatch` (предупреждение) | плановые недели отличаются от календаря больше чем на неделю |
| `estimand_design_mismatch` | `primary_estimand` согласован с дизайном (разница изменений — только для дизайнов со сравнением) |
| `external_analysis_not_acknowledged` | ITS / stepped wedge требуют `analysis_plan.external_analysis_acknowledged = true` |
| `end_date_in_future` (переход) | завершение раньше плановой даты — только с `override_future_end` и причиной |

**ITS и stepped wedge** — `analysis_mode = protocol_only_external_analysis`: OquMap хранит протокол, рандомизацию волн
и журнал реализации, но не рассчитывает результат; предел вывода `external_analysis_required`, повторное измерение →
`409 protocol_only_external_analysis`. UI показывает это на странице пилота и в конструкторе.

### 4.2 Целостность снимка интервенции при запуске
Перед `ready → active` проверяются: хеш сохранённого снимка (`snapshot_sha256`), ссылка снимка на выбранную версию,
неизменность рецензированной версии (пересчёт `content_hash`), совпадение `content_sha256` и канонического содержимого
снимка. Любое расхождение → `409 snapshot_mismatch` с кодами проверок, пилот не запускается, аудит
`pilot.snapshot_mismatch` содержит только коды (без содержимого интервенции). Тесты: `tests/test_integrity.py`.

### 4.3 Ограничения БД и гонки
CHECK: положительная дозировка (версии, пилоты), неотрицательные счётчики журнала, ровно одно поле цели по
`target_type`, причина у решения «остановить». UNIQUE: одна коррекция записи журнала, версия решения в группе.
Составные FK: вывод → результат того же пилота и организации; пилот/запись доказательной базы → версия выбранной
интервенции. Гонки (код интервенции, версия, код пилота — с повтором, коррекция, версия решения) дают 409; общий
обработчик `IntegrityError` → `409 integrity_conflict`. Тесты: `tests/test_robustness.py`.

### 4.4 Календарь занятий (`pilot_sessions`, `pilot_session_events`)
До запуска: черновое расписание по частоте (`POST /pilots/{id}/sessions/generate`: дни недели, даты и диапазоны
каникул), свободное редактирование и удаление (с журналом). После запуска: занятия не удаляются и не меняют
длительность; отмечаются проведёнными/отменёнными или переносятся (исходное занятие → `rescheduled` со ссылкой на новое).
Запись журнала реализации автоматически закрывает совпадающее занятие. Данные по классам — только методист,
утверждающий, учитель. Это календарь конкретного пилота, не школьное расписание.

### 4.5 Experiment Design Studio (`eds-v1`, `POST /design-studio/evaluate`)
Детерминированный аналитический расчёт (без модели ИИ): размеры кластеров (из выбранных классов набора или вручную),
диапазон ICC, корреляция с входным баллом, отсев, диапазон эффекта/желаемый MDE, наличие сравнения, число измерений,
календарь. Формула: `DE = 1 + (m′−1)·ICC`, `Var = (1 − r²)·DE·(1/(J_T m′) + 1/(J_C m′))`, `df = J − 2`,
`MDE = (t_{1−α/2} + t_{мощн.})·SE`, мощность — сдвинутое центральное t. Одна группа: изменение, не эффект. Меньше 5
кластеров в группе — MDE и мощность не показываются. Выход: допустимость с причинами, предел вывода, кластеры по
группам, диапазоны MDE и мощности, таблица чувствительности 3×3, риски контаминации/дисбаланса/общего роста.
Кнопка «Выбрать дизайн» только заполняет форму; протокол проверяет сервер, запуск утверждает человек.
Тесты: `tests/test_design_studio.py` (монотонность по кластерам, ICC, отсеву, информации).
