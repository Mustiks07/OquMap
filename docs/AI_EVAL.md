# Оценка связывания с целями обучения

Скрипт: `scripts/eval_ai_mapping.py` (результат — `data/ai_eval/results.json`).

## Набор
* **fragments** — 25 текстовых маркеров из двух демо-пособий (`apps/api/oqumap/demo/materials.py: GOLD`) с целями,
  которые проставил разработчик.
* **items** — 52 демо-задания с авторской разметкой банка заданий (`content.py`).

Оба набора размечены **разработчиком, а не независимым методистом**, корпус крошечный и на русском языке. Цифры
описывают согласие с этой разметкой, а не внешнее качество. Казахский язык не оценивался.

## Типичные ошибки шаблона
Полный список — `errors` в `results.json`. Наиболее частые: смешение «сравнения» и «приведения к общему
знаменателю» (общие слова), фрагменты-примеры, где правило упоминается косвенно, задания на проценты, которые
одновременно задевают десятичные дроби. Лексикон намеренно не подгонялся под этот набор, чтобы цифры не были
переобучены; поэтому все предложения шаблона имеют статус «предложено» и требуют подтверждения методистом.

## Что ещё нужно для честной оценки
Независимая разметка методистом (≥ 100 фрагментов и заданий), отдельный набор на казахском, измерение доли
отправленных на ручную проверку и доли уверенных ошибок для `live_model`.

## Сравнение провайдеров/моделей (`scripts/eval_llm_provider.py`)
Один и тот же фиксированный набор из 6 синтетических задач для любого настроенного провайдера (Gemini, OpenRouter,
OpenAI, Anthropic): структурированное объяснение на русском (проверка схемы и **выдуманных чисел** через
`verify.check_numbers`), то же на казахском (наличие казахских букв), выбор `evidence_ids` только из разрешённого
списка, три задачи на **выбор инструмента** (сравнение изданий, поиск по материалам, качество данных). Для каждой —
статус, задержка и токены; итог пишется в `data/ai_eval/provider_eval_<provider>_<model>.json`.

```bash
cd apps/api && OQUMAP_LLM_PROVIDER=gemini OQUMAP_LLM_MODEL=gemini-2.5-flash OQUMAP_GEMINI_API_KEY=... \
  uv run python ../../scripts/eval_llm_provider.py
```

**Статус: не запускался ни для одного провайдера** — в среде разработки не было ни одного API-ключа. Сам стенд
проверен тестом `tests/test_provider_eval.py` со сценарным адаптером (ловит выдуманное «37%» и чужой ID). Адаптеры
проверены контрактными тестами на HTTP-фикстурах `tests/fixtures/llm/*.json`; фикстуры составлены по публичной
документации API, **а не записаны с реальных ответов** — форма реальных ответов может отличаться в деталях.
Модель для конкурса следует выбирать по результатам этого прогона, а не по бренду.
