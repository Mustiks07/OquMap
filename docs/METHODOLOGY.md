# Методика OquMap (method versions `scoring-v1`, `std-v1`, `planner-v1`)

Документ описывает, что именно рассчитывает код, на каких предпосылках и где проходят границы интерпретации.
Все формулы реализованы в чистых функциях `apps/api/oqumap/analytics/` и покрыты тестами `apps/api/tests/`.
Числа на экране, в ответах ассистента и в экспорте берутся из одного снимка анализа (`AnalysisRun`).

## 1. Данные и состояния измерения

| Состояние | Как хранится | Как учитывается |
|---|---|---|
| Неверный ответ | `responses.status = answered`, `score = 0` | Измеренный ноль |
| Пропуск задания | `status = omitted`, `score = NULL` | По правилу `omitted_policy`: `as_incorrect` (0 баллов, по умолчанию) или `exclude` (задание исключается из знаменателя ученика). Доля пропусков показывается отдельно |
| Отсутствие ученика | `sittings.status = absent`, ответов нет | Ученик не получает балл (ни 0, ни иного); число отсутствовавших — в исключениях |
| Задание не входило в форму | строки нет | Цель/тема «не измерялась» — никогда не 0% |
| Невалидная строка импорта | не вставляется | Число отклонённых строк — в отчёте импорта и в исключениях темы |

**Правило выбора попытки** (`attempt_rule`): `first` (по умолчанию) — первая попытка ученика по заданию; `last` — последняя.
В обоих случаях на пару (ученик, задание) остаётся одна строка; повторные попытки не создают новых учеников/наблюдений.

**Итоговые оценки** (`kind=grades`) сохраняются для обзора; из них не строится диагностика по темам — система явно
перечисляет недостающие поля (ответы по заданиям, связи заданий с целями, входная проверка, использование изданий).

## 2. Результат по теме

### 2.1 Показатель ученика
Для темы *t* и ученика *i* по выбранным попыткам:

`score_i,t = Σ_j w_j,t · score_ij / Σ_j w_j,t · max_j`

где `w_j,t` — вес задания *j* для темы *t*.

### 2.2 Веса связей «задание → цель»
Веса связей одного задания с целями в сумме равны 1 (`item_objectives.weight`, перенормируются при подтверждении).
Вес задания для темы — сумма весов его связей с целями этой темы. Поэтому задание, связанное с двумя целями одной темы,
учитывается один раз (вес 1), а задание, разделённое между двумя темами, вносит в каждую свою долю. Для показателя
цели используется вес связи с этой целью.

По умолчанию учитываются только **подтверждённые** связи (`mapping_status=confirmed_only`). Тема, у которой есть
только предложенные связи, получает статус «разметка не подтверждена», а не балл. Режим `include_proposed` доступен
явно и отображается в фильтрах и в отчёте.

### 2.3 Агрегация и неопределённость
* `aggregation=learner` (по умолчанию): среднее по ученикам; стандартная ошибка — кластерно-устойчивая по классам
  `SE = sqrt(G/(G−1) · Σ_g (Σ_{i∈g} (y_i − ȳ))²) / N`, интервал `ȳ ± t_{0.975, G−1} · SE`.
* `aggregation=class`: среднее средних по классам, интервал `t_{0.975, G−1} · sd(class means)/√G`.
* При `G < 5` классов интервал не рассчитывается (`ci_unavailable_reason = too_few_clusters`).
* Число ответов никогда не используется как число независимых наблюдений; рядом с долей всегда показываются числа
  учеников, классов и школ.

### 2.4 Статусы тем
`difficult` < 55% ≤ `attention` < 70% ≤ `stable` — условные пороги навигации (не вероятность освоения);
`insufficient_data` — менее 30 учеников или 3 классов; `not_measured` — нет заданий на формах; `unverified_mapping` —
только предложенные связи. **Покрытие** (доля целей темы, измеренных заданиями) выводится отдельно от результата.

Приоритет темы на обзоре = дефицит `1 − mean` среди измеренных тем; неизмеренные темы выводятся отдельным списком
«пробелы измерения».

### 2.5 Ошибки и дистракторы
Для каждого задания: доля верных среди ответивших, доля пропусков, распределение выбора вариантов. Дистракторы
размечены кодами типичных ошибок (`apps/api/oqumap/demo/content.py: MISCONCEPTIONS`). Для темы считается число
учеников, хотя бы раз выбравших дистрактор с данным кодом (кроме `calc_error`). Это **гипотеза для проверки**:
к каждому коду приложено диагностическое задание. Одна ошибка не доказывает устойчивого заблуждения.

## 3. Входной уровень
Входной уровень ученика — доля баллов по всей входной проверке (`stage=pre`, все задания с равными весами по
максимальному баллу, то же правило попыток и пропусков). Схемы групп зарегистрированы заранее (выбор произвольных
порогов через API невозможен):

| Схема | Группы |
|---|---|
| `pre_three_level` (по умолчанию) | low < 0,50 ≤ mid < 0,75 ≤ high |
| `pre_two_level` | low < 0,50 ≤ high |

## 4. Сравнение изданий (`std-v1`)

### 4.1 Оцениваемая величина
Средняя доля баллов по теме в итоговой проверке у учеников классов, работавших по изданию A и B (основное издание
класса для темы из `material_exposures`), в целевой популяции, заданной весами групп входного уровня.

### 4.2 Прямая стандартизация
`adjusted(book) = Σ_k weight_k · mean(book, k)`

Веса (`weight_mode`): `pooled` — состав объединённой выборки обоих изданий (по умолчанию); `equal` — равные;
`arm_a` / `arm_b` — состав одной из групп. Веса фиксируются по исходной выборке и не подбираются под результат.
Если в группе с ненулевым весом у одного из изданий нет учеников, скорректированный показатель **не рассчитывается**
(`empty_stratum`), экстраполяция не выполняется; исходные описательные показатели и таблица групп остаются видимыми.

### 4.3 Неопределённость
Перцентильный кластерный бутстрэп (2000 повторов, фиксированный seed): внутри каждого издания с возвращением
выбираются **единицы назначения**: класс, если издание различается внутри школ; школа, если каждая школа работает по
одному изданию. Веса групп в повторах не пересчитываются. Повторы, в которых пустеет группа с положительным весом,
считаются невалидными; при доле > 5% интервал не выдаётся. При `< 5` единиц на издание интервал не рассчитывается.
Симуляционная проверка покрытия (60 повторов, 16 классов на издание) — `tests/test_comparison.py`. Кластеризация
только по классам при наличии школьных эффектов может занижать неопределённость; это ограничение документировано.

### 4.4 Проверки сопоставимости
| Код | Серьёзность | Смысл |
|---|---|---|
| `forms_not_linked` | fail | Разные формы на разных шкалах без выравнивания — сравнение баллов запрещено |
| `common_items_only` | info | Формы одной шкалы, связанные общими заданиями: результат только по общим заданиям |
| `edition_confounded_with_teacher` / `_school` | fail | Все классы издания — у одного учителя / в одной школе |
| `grade_mismatch` | fail | Разный класс обучения |
| `mapping_unverified` | fail/warn | Связи заданий темы не подтверждены |
| `few_clusters` | warn | < 5 единиц назначения на издание; интервал не рассчитывается |
| `language_mismatch`, `periods_do_not_overlap`, `edition_language_differs` | warn | Различия условий |
| `low_baseline_coverage`, `no_baseline_measure` | warn | Входной уровень известен не у всех / отсутствует |
| `small_stratum` / `empty_stratum` | warn / блокирует | < 10 учеников в группе / пустая группа |
| `mixed_exposure_excluded` | warn | Классы с несколькими основными изданиями исключены |

Итог: `not_comparable` при любой `fail` (кроме пустой группы) — скорректированный показатель скрыт, рейтинг
запрещён; `limited` при предупреждениях; иначе `comparable`.

### 4.5 Уровень вывода
`descriptive` — нет допустимой поправки; `adjusted_association` — стандартизованное сравнение без блокирующих
причин. `causal_protocol` **не выставляется**: исследовательский протокол (рандомизация/контроль, заранее
зарегистрированный анализ) не реализован; поле `causal_protocol_available=false`. Интервал, включающий ноль,
интерпретируется как «данных недостаточно для различения», а не как равенство изданий. Таблица по всем темам
помечена как разведочная (множественные сравнения).

Фактические часы **не** включаются в поправку: они могут быть частью механизма действия издания.

### 4.6 Учебная фикстура
`data/demo/fixtures/composition_fixture.json`: A 144/180 + 8/20 = 76%, B 18/20 + 108/180 = 63%; при весах 50/50
A 60%, B 75%. Числа вычисляются из фикстуры (`/api/v1/fixtures/composition`, тест
`test_composition_fixture_reproduces_76_63_and_60_75`), в UI не зашиты. Иллюстрация не является доказательством
причинности и не используется для интервалов (у каждого издания 4 условные школы — интервал не выдаётся).

## 5. Повторная проверка
Сопоставление «до» (итоговая проверка набора на дату решения) и «после» (проверка `stage=followup`) только на
общих заданиях одной шкалы (`S-POST`, `common_items`). Если шкалы различаются или не связаны — статус
`needs_more_data` с причиной `forms_not_linked`. Когорты «до» и «после» сравниваются той же процедурой `std-v1`
(стандартизация по входному уровню, кластерный бутстрэп по классам). Для группы сравнения (другое издание) считается
то же изменение и описательная «разница изменений». Статусы: `positive_signal` (нижняя граница интервала > 0),
`needs_revision` (верхняя < 0), `not_confirmed` (интервал включает 0), `needs_more_data` (нет интервала/сопоставимости).
Это **наблюдаемая динамика**, а не оценка воздействия; причинный процент улучшения не выводится.

## 6. Планировщик часов (`planner-v1`)
Целочисленная задача CP-SAT:

`maximize Σ_t p_t · U(h_t) − λ · Σ_t |h_t − h0_t|`, `U(h) = (1 − r^h)/(1 − r)`,
`r = 0,5^{1/mean(h0)}` по умолчанию (предельная ценность часа уменьшается вдвое на среднем размере темы).

Ограничения: `Σ h_t = H`; `min_t ≤ h_t ≤ max_t`; зафиксированные темы `h_t = h0_t`; проведённые часы
`h_t ≥ elapsed_t`; `|h_t − h0_t| ≤ max_change_t`. Коэффициенты масштабируются до целых (×1000).

* `p_t` по умолчанию = `deficit_t / max deficit` по измеренным темам; неизмеренные темы получают 0,5 и пометку
  «нужна диагностика» (не обнуляются). Веса видимы, редактируются методистом и версионируются (`priority-weights-v1`).
* Сценарии: `balanced` (λ = 0,05), `minimal_changes` (λ = 0,15), `focus_problem_topics` (λ = 0,015).
* Статусы решателя передаются как есть: `optimal`, `feasible` (найдено допустимое решение, оптимальность не доказана,
  например по таймауту), `infeasible`, `unknown` (ничего не утверждается о невозможности), `invalid`.
* Каждое решение проверяется **независимым валидатором** (`validate_plan`) без участия решателя; при нарушении
  статус `invalid`, план не показывается.
* При `infeasible` каждому ограничению соответствует литерал; CP-SAT возвращает достаточный набор допущений, затем
  удалением по одному строится минимальный конфликт, и каждый элемент перепроверяется повторным решением
  (`verified=true`). Дополнительно выводится арифметика: сумма нижних границ против бюджета.
* Целевая функция — инструмент распределения приоритета, **не прогноз роста баллов**. Результат — план часов по темам;
  календарное расписание по неделям не строится.

Фикстура из задания: исходные `[4,8,4,4]`, допустимый `[3,10,3,4]` при сумме 20, минимумах `[3,8,3,4]`, максимуме
второй темы 10; конфликт «зафиксировать все и добавить 2 часа без резерва» — `tests/test_planner.py`.

## 7. ИИ и проверка ответов
Модель (если настроена) получает только структурированные метрики и фрагменты источников как данные. Любое число в
ответе сверяется с метриками входа (доли допускаются в процентах и п.п.; допуск 0,6); ссылки на источники должны
существовать и принадлежать организации. Не прошедший проверку ответ модели не показывается — используется шаблон,
а отклонённый вариант сохраняется в `verification.rejected_live_output` для аудита. Режим (`live_model`,
`recorded_demo`, `template`) виден пользователю и сохраняется вместе с моделью, версией шаблона, хешем входа и
временем. Самооценка модели не используется как вероятность.

## 8. Чего система не утверждает
* Что одно издание «лучше» в причинном смысле.
* Что доля баллов — вероятность освоения.
* Что демо-корпус (≈800 учеников) обеспечивает статистическую мощность.
* Что перераспределение часов даст конкретный прирост баллов.
* Что коды целей `DEMO-M6-*` совпадают с официальной программой.
