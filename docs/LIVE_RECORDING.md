# Запись настоящего прогона живой модели для офлайн-демо

Обычной работе ключ не нужен: без него ИИ-функции работают в режиме шаблонов, а демо — полностью.
Этот сценарий нужен один раз, когда появится ключ, чтобы «Демо за 3 минуты» могло показать **настоящие ответы
модели без сети** (режим `recorded_demo`). **Записи в репозитории сейчас нет** — её нельзя создать без реального
вызова модели, и фиктивную запись мы не делали.

## Что делает команда
`python -m oqumap.maintenance record-live` (`apps/api/oqumap/ai/record_live.py`):

1. **Отказ, если что-то не так**: провайдер не live (`none`/`recorded`), есть ошибка конфигурации (`check-config`),
   демо не загружено, данные не синтетические.
2. **probe** — запрос возможностей модели у провайдера.
3. **provider eval** — тот же набор из 6 синтетических задач, что `scripts/eval_llm_provider.py` (схема, выдуманные
   числа, ID доказательств, KZ, выбор инструмента, задержка и токены).
4. **консилиум** по теме T3 базового синтетического набора на RU и KZ. Роли Аналитика и Эксперта должны отработать
   в режиме `live_model`; если хоть одна ушла в шаблон (квота, ошибка, отказ модели) — запись отменяется.
   Критик и серверные проверки ID/чисел работают как всегда.
5. **Очистка и запись**. Каждый ответ сначала пишется во временный каталог `data/demo/recorded/.staging-*`.
   Перед записью: в тексте не должно быть значения ключа, похожих на ключи строк (`Bearer …`, `sk-…`, `AIza…`,
   имён заголовков) и e-mail-адресов, иначе запись прерывается. UUID базы заменяются на `<ID1>…` во входе и в
   ответе, поэтому запись воспроизводится и в одноразовых копиях демо (там другие ID), а ID в ответе
   подставляются из текущего запроса.
6. Только после успеха всех шагов файлы переносятся в `data/demo/recorded/llm/`, создаётся `MANIFEST.json`
   (провайдер, модель, политика данных, возможности, итог eval, версия синтетического набора, sha256 файлов).
   При любой ошибке временный каталог удаляется.

## Как запустить, когда появится ключ
Только синтетические данные; для бесплатного Gemini это обязательно (политика `may_train`).
```bash
cd apps/api
export OQUMAP_LLM_PROVIDER=gemini OQUMAP_LLM_MODEL=gemini-2.5-flash
export OQUMAP_GEMINI_API_KEY=...            # только в окружении; не сохраняется и не печатается
uv run python -m oqumap.maintenance check-config
uv run python -m oqumap.maintenance probe-llm
uv run python -m oqumap.maintenance record-live            # опции: --topics T3,T5 --langs ru,kz --no-eval
```
Результат: `{"recorded": true, "provider": …, "model": …, "files": N, "eval": {…}}` или `{"recorded": false,
"refused": "…"}` (код выхода 2). Затем просмотрите `data/demo/recorded/llm/*.json` глазами (это синтетические данные
и ответы модели) и закоммитьте их.

## Воспроизведение
```bash
OQUMAP_LLM_PROVIDER=recorded docker compose up
```
Консилиум и объяснения берут записанные ответы и подписаны **«Записанный демо-пример (не живой анализ модели)»** —
никогда как `live_model`. Если запрос не совпадает с записью (другие данные, другая версия набора), используется
шаблон, причина видна в `fallback_reason`.

## Проверки
`apps/api/tests/test_recording.py`: нормализация ID и воспроизведение в другом арендаторе; отказ при значении
ключа, `Bearer`, `sk-`, `AIza`, e-mail; полный прогон `record()` со сценарным тестовым адаптером во временный
каталог (в репозиторий ничего не пишется) и воспроизведение консилиума в режиме `recorded_demo`; отказ без
live-провайдера.
